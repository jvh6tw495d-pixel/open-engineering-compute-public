## 2. What 2.6.2 contains

### Migrated legacy skills (thin-wraps, contract preserved)

| Skill | Previous owner | New delegation | Public contract |
|-------|----------------|----------------|-----------------|
| `battery.soc_step` | `oec.kernel.energy.metrics.soc_update` | `oec.physics.storage.energy_based_soc_update` | `{value, unit}` unchanged, output shape identical |
| `energy.balance` | kernel `energy.metrics` residual check | `oec.physics.conservation.evaluate_residual` (`rtol=0` preserves legacy absolute tolerance) | `{value, unit}` unchanged; `ConservationError` when both `energy_in` and `energy_out` are empty |

**Thin-wrap pattern:** the skill delegates numerical work to the physics owner while preserving the public id / input / output schemas and output shape. Because the kernel already delegatess to `oec.physics`, parity is structural — confirmed by the side-by-side harness with **shape bit-identical** output (not merely close).

### Naming corrections (docstring / metadata only; zero numerical change)

- `skills/battery/soc_step/skill.yaml` — title `"Battery SOC Step (Coulomb Counting)"` → `"Battery SOC Step (Energy-Based)"`; `method.id` `coulomb_count_step` → `energy_based_step`; description → *"Generic energy-based SOC integration (power × time × efficiency / capacity)"*. `battery.soc_step` **is not** ampere-hour coulomb counting — the old label was wrong.
- `skills/battery/soc_step/skill.md`, `skills/energy/balance/skill.md` — front matter synced to `skill.yaml` (version `0.2.1`), resolving the `SkillFrontMatterError`.
- `src/oec/kernel/energy/metrics.py` `soc_update` docstring — `"Coulomb-counting SOC step"` → `"Energy-based SOC step (generic)"` (kernel computes `delta_e = power * dt_hours * efficiency` then `/ capacity`).

**Operator note — Ruff version skew:** the repo `.venv` ships `ruff 0.16.0` while pre-commit pins `ruff-pre-commit v0.6.9` (`.pre-commit-config.yaml`). The two formatters disagree (1-line vs multi-line wrapping). During this release a pre-commit stash+rollback cycle **reverted uncommitted edits and blocked commits** when the working tree carried modified-unstaged files. Workarounds used: (a) keep **all** release files staged so the hook stashes nothing, (b) format/stage with the hooked Ruff (`~/.cache/pre-commit/<repo>/py_env-*/Scripts/ruff.exe`) as the canonical formatter, (c) recover lost edits via `git apply --include=<files>` from the stash patch (`~/.cache/pre-commit/patch*`).
