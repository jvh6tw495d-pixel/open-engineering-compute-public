## 1. Pipeline de 3 modelos

| Papel | Modelo | Responsabilidade | Quando atua |
|-------|--------|------------------|-------------|
| **EXECUTOR** | Grok Build CLI | Implementa código, testes, wiring, merges locais, commits/PRs | Após gate Opus (waves major) ou continuamente em micro-tasks |
| **REVISOR TÉCNICO** | Claude Sonnet | Diff quality, cobertura, naming, testes, aderência ao plano, suite verde | Após cada PR/commit significativo da wave |
| **GATE ARQUITETURAL** | Claude Opus 5 | Design, riscos, lacunas, go/no-go **antes** de implementar a wave | Antes de Wave 1, 2, 3 (major); opcional re-gate se Sonnet flagar design change |

### Regras de alternância (anti-gargalo)

1. **Opus não revisa diffs de rotina.** Só gates de wave + re-gate se Sonnet detectar desvio de contrato (shape, status overload, novo tool, double-wrap).
2. **Sonnet não bloqueia kickoff de helpers unitários** se o gate Opus da wave já passou; revisa o PR em paralelo com o próximo micro-task do Grok.
3. **Grok nunca avança wave major sem GO do Opus** (W1/W2/W3). Waves 0, 4, 5: Opus opcional (checklist curto).
4. **Paralelismo:** Wave 3 (vereditos transport + OEC) pode começar quando Wave 1 mergear; veredito host-corruption espera Wave 2. Sonnet revisa Wave 1 PR enquanto Opus prepara gate Wave 2.
5. **Um executor por branch.** Grok implementa; Sonnet/Opus só leem e emitem veredito em artefato (seção 8).

## 11. Critérios que **disparam** re-gate Opus mid-wave

Sonnet (ou Grok) escala para Opus se qualquer um:

1. Proposta de **novo** MCP tool
2. Mutar `ExecutionResult` / quebrar `frozen` / `extra=forbid`
3. Wrap em `_run_specialist_by_name` ou double envelope
4. Alterar semântica global de `status` / top-level `result`
5. Curated domain `values` (fora do “verbatim `execution.result`”)
6. Expandir envelope para REST/SDK na mesma release
7. Falha Wave 4 ambígua (não é óbvio se é OEC vs host vs transport)
8. Mudança de `AUTHORITATIVE_ANSWER_SCHEMA_VERSION` major
9. Divergência: tolerâncias que mudam contrato host (breaking)

Resposta Opus: `RE-GATE: GO with constraints | NO-GO + redirect`.
