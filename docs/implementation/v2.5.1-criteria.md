# OEC v2.5.1 Criteria

**Date:** 2026-07-29
**Branch target:** `codex/oec-v2.5`
**Intent:** refinement release immediately after the v2.5 hard-gate work, focused on coherence, missing time-series modeling coverage, and honest closeout of known residuals.

## 1. Positioning

`v2.5.1` is **not** a new platform wave and **not** the start of Physics / Chemistry / Multiphysics.

It is a **stabilization and refinement release** with four goals:

1. reconcile the published product picture with the real repository state;
2. close the most visible domain gap exposed by model-facing tests;
3. improve `agent.default` routing where the contract already promises generic entry;
4. reduce the highest-value residual risk left after the `v2.5` gate.

## 2. Why `v2.5.1` exists

The repository now contains materially more capability than the public inventory currently describes.

Current published inventory:

- `docs/implementation/skill-inventory.md` still describes **40** skills.

Current repository reality (directory count under `skills/`):

- **63** skill packages across mathematics, optimization, timeseries, statistics, electrical, linear, uncertainty, finance, control, dynamics, energy, and battery.

This mismatch is now large enough that a refinement release should correct product truth before expanding into new scientific domains.

In addition, recent model-facing tests exposed a concrete missing capability:

- the OEC can route simple natural-language mathematics requests more reliably than before,
- but it still lacks governed skills for classic autoregressive / autocorrelation-based time-series estimation such as Yule-Walker and Levinson-Durbin.

## 3. Release Thesis

`v2.5.1` succeeds if it makes the OEC **more honest, more callable, and more useful** without broadening the scientific scope beyond Mathematics Complete.

That means:

- better catalog truth;
- better time-series statistical coverage;
- better default routing behavior;
- better evidence on the weakest kernels;
- no speculative domain expansion.

## 4. In Scope

### 4.1 Documentation and product truth

Required:

- update `docs/implementation/skill-inventory.md` to reflect the real skill catalog;
- update any nearby implementation/status docs that still describe the catalog as `~40` skills when the repository now contains `63`;
- align release-facing documents with the actual branch state and package status;
- close the package metadata/version truth gap if `v2.5` is declared complete enough to justify `v2.5.1`.

Acceptance:

- published inventory count matches the real `skills/` tree;
- domain counts in docs are reproducible from the repository;
- no major implementation/status doc materially understates the shipped catalog.

### 4.2 Time-series advanced modeling gap

Required minimum package for `v2.5.1`:

- `timeseries.autocorrelation`
- `timeseries.pacf`
- `timeseries.ar_yule_walker`
- `timeseries.levinson_durbin`

Optional stretch, only if the minimum package is already green:

- `timeseries.ar_burg`

These skills should cover:

- autocorrelation / normalized autocorrelation extraction;
- PACF computation with explicit method disclosure;
- AR coefficient recovery from measured autocorrelation;
- innovation variance reporting;
- Toeplitz-structured solve path and its diagnostics;
- clear assumptions and failure modes.

Acceptance:

- each new skill has schema, implementation, references, validation, and golden tests;
- each skill reports through the standard `ExecutionResult` contract;
- at least one end-to-end MCP/SDK integration path proves the skills are callable through governed interfaces;
- no invented numerical claims beyond the supplied inputs.

### 4.3 `agent.default` refinement

Required:

- extend `agent.default` routing so that requests containing autoregression / autocorrelation / PACF / Yule-Walker / Levinson-Durbin intent are routed to the correct governed path;
- preserve the existing rule that explicit `skill_id + inputs` wins over heuristic routing;
- keep domain inference explainable and testable.

Acceptance:

- integration tests show that generic natural-language requests in this domain do not fail with the old “provide `preferred_domain`, `demo_label`, or `skill_id+inputs`” behavior when a governed route exists;
- explicit skill requests still bypass heuristic routing safely;
- vague requests that still cannot be grounded fail honestly rather than hallucinating a route.

### 4.4 Coverage push on highest-value residuals

Required focus modules:

- `src/oec/kernel/timeseries/quality.py`
- `src/oec/kernel/timeseries/ops.py`
- `src/oec/kernel/timeseries/timegrid.py`
- `src/oec/kernel/optimization/feasibility.py`

Second-tier candidates if time remains:

- `src/oec/kernel/control/kalman.py`
- `src/oec/kernel/optimization/robust.py`
- `src/oec/kernel/optimization/pareto.py`
- `src/oec/kernel/optimization/qp.py`
- `src/oec/kernel/optimization/cvar.py`

Acceptance:

- new tests target the actual untested branches called out in `v2.5-critical-path-coverage.md`;
- kernel coverage improves measurably, especially in time-series modules;
- no coverage improvement is claimed from duplicated or low-signal parametrization.

## 5. Out of Scope

Explicitly out of scope for `v2.5.1`:

- Physics domain build-out;
- Chemistry domain build-out;
- multiphysics coupling;
- large new electrical/energy programs unrelated to the immediate catalog gap;
- broad control/dynamics expansion;
- agentic orchestration redesign beyond domain-routing refinement;
- authentication/rate-limiting for REST/MCP;
- OS-level sandbox isolation;
- multi-tenant or remote-release governance.

Those are valid future programs, but they are not refinement-release work.

## 6. Entry Criteria

`v2.5.1` work may start when all of the following are true:

- the branch state used as baseline is identified explicitly;
- the current documentation mismatch is acknowledged rather than worked around;
- the release is framed as a refinement release, not a new domain wave;
- no unreviewed physics/chimistry scope is bundled into the same packet.

## 7. Exit Criteria

`v2.5.1` is ready only if all of the following are true:

1. The inventory truth gap is closed in docs.
2. The minimum AR/time-series package is implemented and tested.
3. `agent.default` can route at least one advanced time-series request class through governed skills.
4. Critical weak spots in time-series kernel coverage improve with direct evidence.
5. Full local validation passes for the touched scope.
6. The release notes distinguish clearly between:
   - newly added governed capabilities;
   - improved routing behavior;
   - documentation reconciliation;
   - residual limitations that remain open.

## 8. Recommended Validation Pack

Minimum validation pack:

- targeted unit and golden tests for each new time-series skill;
- integration tests for `agent.default` routing into the new governed path;
- inventory reconciliation check against the real `skills/` tree;
- focused coverage measurement on the touched kernel modules;
- full lint/format/type/test suite already used by the branch.

Recommended scenario tests:

- AR coefficient recovery from known autocorrelation values;
- PACF behavior on a known AR(1) or AR(2) synthetic case;
- failure on malformed/non-PSD or insufficient autocorrelation input where appropriate;
- MCP invocation from a natural-language prompt that previously failed or degraded to unguided text.

## 9. Non-Goals Disguised as Goals

The following do **not** count as `v2.5.1` success by themselves:

- adding more skill count without closing the routing gap;
- claiming “better AI behavior” without governed skill support;
- publishing broad roadmap language without inventory reconciliation;
- raising aggregate coverage while leaving the weakest time-series kernels effectively untouched.

## 10. Practical Definition of Done

`v2.5.1` is done when a reviewer can truthfully say:

> The OEC catalog is documented accurately, the default router is more faithful
> to its contract, and the product now covers the missing AR/autocorrelation
> class with governed, test-backed time-series skills.

If that sentence is not true, the release is not done.
