### D4 — P1 canónico: **DC linear power flow meshed** — **FECHADO pré-GATE-W1** (movido da Wave 3 → Wave 1)

**Problema (Codex):** “DC power flow v0 / radial” como alternativas **não** é contrato — entradas, hipóteses e oracles diferem.

| Opção | Descrição | Veredito |
|-------|-----------|----------|
| **(a) escolhida** | **DC linear power flow meshed** — modelo linear de fluxo de potência activa em grafo malhado (B-matrix / susceptâncias), 0D/1D de rede | **Aceite — canónico P1 v0** |
| (b) | Radial branch-flow simplificado | **Diferido** — extensão opcional pós-2.6; **não** entra no gate mínimo |

**Contrato canónico P1 v0 (`dc_power_flow`):**

| Aspecto | Fixo |
|---------|------|
| **Nome API** | `oec.physics.electrical.dc_power_flow` (ou `electrical_network.dc_power_flow`); skill `electrical.dc_power_flow` |
| **Entradas** | topologia de linhas (from/to); susceptância `B_ij` (ou reactância `X_ij` com `B=1/X` documentado); injecções activas `P_i` por barramento (pu ou W canónico); barramento de referência (slack) |
| **Saídas** | ângulos θ (relativos ao slack); fluxos de linha P_ij; residual de balanço por nó; flag `balanced` |
| **Hipóteses** | rede linear; perdas resistivas negligenciadas no modelo DC clássico; |V|≈1 pu flat; só potência activa; regime estacionário; grafo conexo |
| **Oracles / checks** | KCL: residual de injecção + fluxos ≈ 0 por nó (tol dimensional D5); soma de injecções ≈ 0 (rede sem perdas no modelo DC); determinismo ADR 0004 |
| **Unidades** | documentar na tabela canónica W2: ângulo rad (ou deg se declarado); potência W ou pu com base explícita |
| **Fora de P1 v0** | AC power flow; OPF; máquinas; sequências; radial-only branch-flow como **substituto** do canónico |

**Onde fixar no pipeline:** decisão e nomenclatura **congeladas na Wave 1** (API pública / tipos / docs) **antes** da implementação numérica completa na Wave 3. GATE-W3 só verifica aderência a este contrato — **não** reabre DC vs radial.

**Referências:** este plano (histórico “DC ou radial”); auditoria Codex §B risco 2; V3 §10 P1.

### D5 — Ownership de conservação + tolerâncias dimensionais — **FECHADO pré-GATE-W1**

**Problema (Codex):** risco de duas fórmulas independentes (`oec.physics.conservation` vs `kernel.energy.energy_balance`) e tolerâncias absolutas genéricas sem escala/unidade.

| Papel | Owner | Veredito |
|-------|-------|----------|
| **Fonte de verdade de conservação genérica** | **`oec.physics.conservation`** | **Aceite** — API generalizada (energia, carga, massa/continuidade, residual multi-domínio) |
| **Consumidor / adapter energy-fino** | `oec.kernel.energy.metrics.energy_balance` | **Aceite** — permanece API estável do kernel; **não** forka fórmula. Em 2.6.0: parity documentada (mesma semântica residual Σin − Σout − Δstorage). Em 2.6.1+: pode thin-wrap chamar conservation **sem** mudar golden se números idênticos. **Nunca** duas implementações divergentes do mesmo residual |
| Inversão (kernel canónico, physics só reexporta) | | **Rejeitado** — kernel.energy é fatia fina de energia; multi-domínio exige owner em `oec.physics` |

**Política de tolerância (normativa, ADR 0025 + `conservation`):**

```
balanced  ⇔  |residual| ≤ atol + rtol × scale
```

| Símbolo | Significado |
|---------|-------------|
| `residual` | desequilíbrio na **unidade canónica do balanço** (W, Pa, kg/s, pu, J, …) |
| `atol` | tolerância absoluta na mesma unidade do residual |
| `rtol` | tolerância relativa adimensional |
| `scale` | escala característica do problema (ex.: max(|termos do balanço|), ou capacidade / fluxo de referência documentado) |

**Regras:**

1. Toda check de conservação **regista** `atol`, `rtol`, `scale`, **unidade do residual** e política (documentada no result / ConservationCheck).
2. Proibido “tol=1e-6” universal sem unidade/scale em checks multi-domínio.
3. Domínios diferentes **não** partilham o mesmo `atol` default cego; defaults por domínio na tabela canónica W2.
4. `kernel.energy.energy_balance` (API legada com `tolerance: float`) **não** é reescrita em 2.6.0 (zero churn); parity tests documentam equivalência; evolução para `atol+rtol×scale` no kernel fica debt explícito ou 2.6.1 se tocar energy.

**ADR:** ownership e fórmula única em **ADR 0024** (architecture) + detalhe de tol em **ADR 0025**; **ADR 0027 (2.6.1) herda e não reabre** (ver plano irmão).

## 1. Pipeline de 3 modelos

| Papel | Modelo | Responsabilidade | Quando atua |
|-------|--------|------------------|-------------|
| **EXECUTOR** | Grok Build CLI | Implementa código, testes, wiring, merges locais, commits/PRs | Após gate Opus (waves major) ou continuamente em micro-tasks |
| **REVISOR TÉCNICO** | Claude Sonnet | Diff quality, cobertura, naming, testes, aderência ao plano, suite verde | Após cada PR/commit significativo da wave |
| **GATE ARQUITETURAL** | Claude Opus 5 | Design, riscos, lacunas, go/no-go **antes** de implementar a wave | Antes de Wave 1, 2, 3, 4 (major); opcional re-gate se Sonnet flagar design change |

### Regras de alternância (anti-gargalo)

1. **Opus não revisa diffs de rotina.** Só gates de wave + re-gate se Sonnet detectar desvio de contrato (layering, import cycle, domínio privado, novo tool MCP, mutação do envelope, fuga de escopo para energy-rich ou multiphysics, reabrir D3–D7).
2. **Sonnet não bloqueia kickoff de helpers unitários** se o gate Opus da wave já passou; revisa o PR em paralelo com o próximo micro-task do Grok.
3. **Grok nunca avança wave major sem GO do Opus** (W1/W2/W3/W4). Waves 0, 5, 6: Opus opcional (checklist curto) salvo ambiguidade de smoke.
4. **Paralelismo:** dentro da Wave 3, fatias P2/P3/P4/P5 podem avançar em micro-seqs paralelas **após** objetos de domínio + conservation estáveis; skills (W4) só após núcleo físico mergeado. Rascunhos de schemas/ADR docs-only podem seguir em paralelo a W2/W3 **sem** merge de skill code. Docs de closeout (W6) podem ser draftados após W3.
5. **Um executor por branch.** Grok implementa; Sonnet/Opus só leem e emitem veredito em artefato (seção 13).
6. **Forbidden names:** qualquer PR que introduza termo do gate `scripts/check_forbidden_names.py` → **NO-GO automático** (Sonnet ou CI); não é “nit”.
