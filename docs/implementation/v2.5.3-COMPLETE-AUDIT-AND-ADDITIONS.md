## 3. Avaliação do plano v2.5.3

### 3.1 O que o plano acerta (manter)
Diagnóstico correto (OEC protege método/execução, não o contrato de consumo do host); 9 shapes inventariadas; wrap único em call_tool; envelope aditivo (não mutar ExecutionResult frozen/extra=forbid); comparação pós-default=str; não criar tool novo; Waves 1→5 com dependências.
→ Plano executável para Wave 1; INCOMPLETO como hardening de produção.

### 3.2 Lacunas e acréscimos obrigatórios

#### A. Testes de divergência espúria (quase ausentes)
Wave 2 não tem a matriz de falsos positivos:
- Float IEEE `1.0` vs `1` → coerção numérica canônica
- Tolerância abs/rel não especificada → constantes versionadas + tests property
- `QuantityValue {value,unit}` vs número bare → comparador dimensional
- Ordem de chaves / chaves extra → policy subset vs exact
- `null` vs ausência → equivalência explícita
- Listas reordenadas/truncadas → length fail-closed + element-wise
- Consistência agregados (sum≈total) → fixtures golden
- NaN/Inf → fail-closed
- Claim parcial só de subconjunto → spec: subset OK se bate
- Re-serialização double → fixture round-trip

→ Aceite: `tests/unit/test_envelope_divergence.py` ≥12 casos "must_not_flag" + ≥8 "must_flag"

#### B. Serialização (subespecificada)
- Dois pipelines de JSON (model_dump(mode="json") vs default=str) → definir UMA canônica
- datetime/Enum stringificados → ISO-8601 canônico + testes de timestamp
- Numpy escalares em result → converter antes da authority
- Envelope aditivo + result aninhado + execution espelhado → spec de tamanho (authoritative_answer.values = execution.result SÓ)
- Hash de comparação → json.dumps(sort_keys=True, separators=(",",":"))

#### C. Validação de schema strict
- SEM output JSON Schema do envelope → publicar authoritative_answer.schema.json v1.0
- Sem validação runtime do envelope emitido → jsonschema.validate em tests
- claimed_answer sem schema de conteúdo → schema mínimo
- Input schemas incompletos (agent.optimization_specialist) → CORRIGIR na Wave 1/2
- validate_input=False → documentar + flag strict p/ CI
- status:"ok" novo → schema enum de agent-tool status
- kind taxonomy aberta → tabela fechada v1.0 (prefix→kind + fallback generic_result)

#### D. Performance do envelope
- Deep copy → shallow mirror de refs imutáveis
- json.dumps 2–3× por call → comparar só values; microbench p95 < 5ms
- Trajetórias longas 2× → custo aditivo documentado
- lock Engine → normalize fora do lock se mover o wrap

#### E. Versionamento do envelope / compat
- Política semver do envelope (minor aditivo; major se renomear/remover keys)
- Campo obrigatório authoritative_answer_schema_version em toda resposta
- Compat hosts antigos: aditivo OK
- Proibição: reutilizar top-level status com valores de ExecutionStatus
- Golden JSON fixtures por shape (1–9) com snapshot versionado
- Migração 1.1: fallback documentado
