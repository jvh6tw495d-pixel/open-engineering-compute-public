# v2.5 public-API documentation audit (gate item: "docs API pública 100%")

**Date:** 2026-07-28
**Branch:** `codex/oec-v2.5`

The v2.5 gate (`OEC_V3_IMPLEMENTATION_PLAN.md` §9) requires "docs API
pública 100%" but no tool or defined surface existed to measure it before
this session.

## 1. What "public API" means here

The single shared entrypoint every caller goes through, plus every
transport adapter built on it, plus the contract shapes those adapters
pass through unchanged (ADR 0005):

- `src/oec/sdk.py` — the `Engine` facade (SDK).
- `src/oec/cli/main.py` — the `oec` CLI.
- `src/oec/api/app.py` — the REST API.
- `src/oec/mcp/server.py` — the MCP server.
- `src/oec/execution/models.py` — `ExecutionRequest`/`ExecutionResult`/
  `ExecutionStatus`, the shape every adapter returns.
- `src/oec/errors.py` — the `OECError` taxonomy every adapter surfaces.
- `src/oec/ops/models.py`, `src/oec/ops/schema.py` — the OPS problem
  contract (optimization skills' input shape).

This is a narrower, deliberately different list from the "critical path"
coverage definition in `v2.5-critical-path-coverage.md` — that one is
about *scientific correctness modules*; this one is about *what a caller
reads to understand the shape of what they get back*. `src/oec/kernel/`
and `src/oec/validation/` are internal to how a result is computed, not
part of the public contract a caller programs against.

## 2. Tooling

New `scripts/audit_public_api_docs.py` (static `ast`-based, matching the
convention of `scripts/check_forbidden_names.py` / `audit_physical_units.py`
— no import side effects, so it runs identically regardless of which
optional extras (`api`, `mcp`) are installed). For each file in the list
above, it walks every **public** (non-underscore) module-level function,
module-level class, and public method inside those classes, and checks
`ast.get_docstring(...)` is non-empty. Pydantic/dataclass-generated dunders
(`__init__`, `__repr__`, `__eq__`, `__hash__`, `__post_init__`, `__str__`)
are excluded — the class's own docstring already documents the shape they
serialize.

```bash
uv run python scripts/audit_public_api_docs.py
```

Exit code 1 and a line-numbered list on any gap; exit 0 and a coverage
line otherwise.

## 3. Result

**Before:** 36/41 (87.8%) — 5 undocumented:

| File | Symbol | Fix |
|---|---|---|
| `src/oec/cli/main.py:68` | `main` (the `@app.callback()` entrypoint) | added a one-line docstring |
| `src/oec/ops/models.py:14` | `OPSVariable` | added: one decision variable's name/kind/bounds/objective coefficient |
| `src/oec/ops/models.py:24` | `OPSConstraint` | added: one linear constraint's shape |
| `src/oec/ops/models.py:33` | `OPSObjective` | added: the linear objective's shape |
| `src/oec/ops/models.py:40` | `OPSExecutionLimits` | added: solver execution limits |

All five were one-line, no-behavior-change additions (no schema/API
change — these are `pydantic.BaseModel` field containers whose shape was
already fully declared by their field annotations; the docstrings
document intent, not new constraints).

**After: 41/41 (100.0%).**

## 4. Verdict

**Gate item met**, for the public-API surface as scoped above. This is a
docstring-presence gate (a symbol has *some* documentation), not a
docstring-quality gate — it does not check that a docstring is accurate,
complete, or kept in sync with behavior. That remains a code-review
concern, same as for any other comment.
